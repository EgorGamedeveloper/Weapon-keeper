# Сюжет: граф квестов, рации и триггеров

Сюжет игры собирается визуально, в веб-редакторе, как Shader Graph: ноды соединяются «нитками». Потом граф импортируется в Unity, и игра идёт по нему:
- открывает квесты;
- устраивает переговоры по рации;
- ждёт действий игрока;
- выдаёт награды и включает объекты.

- **Редактор** — один и тот же в двух видах (исходник — `Tools/StoryEditor/story_editor.html`):
  - **приложение для Mac** «Weapon Keeper Story» — правит граф прямо в проекте, с историей версий (см. [ниже](#приложение-для-mac));
  - **страница** https://claude.ai/artifact/P8aAP6hr6d9pWyf9W1pciN (или в Unity: **Tools → Weapon Keeper → Story → Open Story Editor**) — граф хранится на странице, открывается с любого устройства.
- **Файл графа в проекте**: `Assets/01_GAME/08_Story/story_graph.json`.
- **Код**: `Assets/01_GAME/01_Scripts/Story/` (рантайм) и `Editor/Story/` (меню).

## Как работать

1. **Один раз — каталог сцены.** Откройте `TestScene` → **Tools → Weapon Keeper → Story → Export Scene Catalog**.
   - Объектам без `PersistentId` пункт предложит его добавить. Если согласились — сохраните сцену.
   - Получится `08_Story/scene_catalog.json`. Загрузите его в редактор («Каталог») или закоммитьте и попросите Claude. Тогда цели (дверь склада, щиток лифта, полка патронов…) выбираются из списков, а не вписываются GUID-ами.
2. **Один раз — перенос текущих квестов** (по желанию): **Story → Export Existing Quests To Graph**.
   - Квесты `QuestManager` превратятся в стартовый граф.
   - Связи между ними берутся из `prerequisiteQuests`, требования к уровню — из `requiredLevel`.
   - Откройте файл в редакторе («Открыть JSON»).
3. **Рисуйте сюжет в редакторе.** «Проверка» показывает ошибки: красное нужно исправить до импорта.
4. **Перенесите граф в проект** одним из способов:
   - в приложении для Mac ничего делать не нужно — граф уже в проекте;
   - «Скачать JSON» и положить файл в `Assets/01_GAME/08_Story/story_graph.json`;
   - написать Claude «синхронизируй граф» — он заберёт граф со страницы и сделает PR.
5. **Импорт**: **Tools → Weapon Keeper → Story → Import Story Graph**. Он:
   - проверяет граф;
   - создаёт или обновляет ассеты квестов (`04_Data/Quests/Story/`, существующие квесты с тем же id обновляются на месте);
   - пишет названия и описания квестов в `strings.csv`;
   - ставит в `TestScene` объект `Story` (`StoryDirector`), интерфейс рации и модель рации в руке и связывает всё с сейвом.

   Повторный импорт безопасен.

## Ноды

Нода включается, когда пришла **любая** входящая нитка. «И» — когда пришли **все**.

| Нода | Когда завершается | Что задаётся |
|---|---|---|
| **Старт** | сразу | начало новой игры |
| **Квест** | квест выполнен | id, название и описание на всех языках, тип (отмыть / починить / расставить / доставить), цель, количество, опыт, деньги |
| **Рация** | разговор закончен | кто говорит, портрет, реплики с длительностью |
| **Триггер** | игрок сделал нужное | вид триггера и его цель (см. ниже) |
| **Ожидание** | через N секунд игрового времени | секунды |
| **И** | все входящие ноды завершены | — |
| **Событие** | сразу | дать деньги, дать опыт, включить или выключить объект сюжета |
| **Заметка** | — | текст для себя, в игре не участвует |

Отдельные правила:
- **Триггер без входящих ниток** слушает с начала игры: «когда бы игрок ни сломал эту дверь — откроется квест».
- **Условие триггера уже выполнено**, когда он начал слушать (например, дверь сломали раньше), — триггер срабатывает сразу.

### Виды триггеров

- починена точка ремонта / сломан объект / отмыто пятно — конкретный объект из каталога;
- на полках категории стоит N предметов;
- в зону доставки принесли предмет (зона и предмет — по желанию);
- подобран предмет;
- достигнут уровень, восстановление здания ≥ %, на счету ≥ денег;
- убит враг — с конкретной точки спавна и/или определённого типа, N раз (враги, поставленные руками, а не точкой спавна, не считаются);
- собран заказ (коробка запечатана), отправлен заказ;
- приехал или открыт ящик поставки;
- выполнен квест вне графа.

Счётчики N у событий (убитые враги, отправленные заказы, ящики) считаются с момента, когда триггер начал слушать, и после загрузки сейва начинаются заново. Триггеры по состоянию (полки, уровень, деньги, ремонт) после загрузки проверяют сцену сами.

**Добавить новый вид триггера:**
1. Класс-наследник `StoryTrigger` в `Story/StoryTriggerKinds.cs`.
2. Строка в `StoryTrigger.Registry`.
3. Строка в списке `TRIGGERS` в `Tools/StoryEditor/story_editor.html`.

## Рация в игре

1. Нода «Рация» включилась → вверху экрана плашка «Входящий вызов по рации — [E] Ответить», рация пищит.
   - Вызов ждёт ответа.
   - На паузе и в открытом окне (навыки, терминал) плашка прячется.
2. **E** — ответить:
   - HUD гаснет;
   - оружие убирается;
   - предмет из рук прячется;
   - перед камерой поднимается рация;
   - внизу идёт строка: имя и «печатающийся» текст.
3. **E** во время разговора: первое нажатие допечатывает реплику, второе переходит к следующей. Без нажатий реплики листаются сами по длительности.
4. Конец — рация опускается, всё возвращается.

Ходить и смотреть во время разговора можно. Брать предметы, переключать режим и стрелять — нельзя. Несколько вызовов подряд идут по очереди.

Настройка в `TestScene` → объект `RadioCallUI`:
- **Портреты**: список `portraits` (id → картинка); id вписывается в поле «Портрет» ноды.
- **Звуки**: `ringClip` / `answerClip` / `hangUpClip`. Сейчас стоят сгенерированные заглушки из `08_Story/Audio`.
- **Модель**: `radioModel`. Сейчас стоит рация из примитивов под камерой — замените своей моделью и подберите `raisedLocalPosition`.
- **Скорость печати**: `charsPerSecond`.

Тексты рации хранятся в самом графе, на всех его языках (кнопка «Языки» в редакторе). Игра берёт текущий язык, а если перевода нет — английский. Названия квестов импорт дублирует в `strings.csv`, потому что их показывают список квестов и HUD.

## Объекты сюжета

Нужно убрать завал после разговора или показать ящик после квеста?
1. Повесьте на объект компонент `StoryObject` и задайте `storyId`.
2. Обновите каталог.
3. В редакторе выберите объект в ноде «Событие → Включить/Выключить объект».

После загрузки сейва объекты сами приходят в нужное состояние.

## Сохранение

Сейв хранит только пройденные ноды (`SaveGameData.storyDoneNodes`). При загрузке:
- квесты продолжаются с сохранённого прогресса;
- недослушанный разговор придёт заново;
- награды нод «Событие» не повторяются.

Если после выхода игры изменить граф:
- удалённые ноды из сейва просто игнорируются;
- новые ноды включатся, как только станут достижимы.

Не меняйте id уже вышедших квестов: по ним сейв находит квест.

## Приложение для Mac

**Установка.**
1. Скачайте `WeaponKeeperStory-<версия>.dmg`:
   - из релиза `story-editor-v…` на GitHub (Releases);
   - или из последнего запуска **Actions → Story Editor (Mac)**, артефакт `WeaponKeeperStory-mac`.
2. Откройте .dmg и перетащите приложение в «Программы».
3. Первый запуск. У приложения нет платной подписи Apple, поэтому macOS спросит один раз:
   - дважды щёлкните — macOS откажется открыть → **Системные настройки → Конфиденциальность и безопасность** → внизу «Всё равно открыть»;
   - если пишет, что приложение «повреждено», выполните в Терминале `xattr -dr com.apple.quarantine "/Applications/Weapon Keeper Story.app"` и откройте снова.
4. Укажите папку Unity-проекта (ту, где лежит `Assets`). Приложение её запомнит; сменить — **Файл → Открыть папку проекта**.

**Как хранятся данные.**
- Граф — `Assets/01_GAME/08_Story/story_graph.json` в проекте, каталог — `scene_catalog.json` рядом (загружается сам при открытии).
- Правка записывается через секунду. Запись атомарная: сбой посреди записи не оставит полуфайл.
- Закрытие окна (Cmd+Q, крестик) ждёт, пока всё запишется. Если записать не удалось, приложение предупредит и не закроется молча.
- **Черновик**: пока правка не записана, она лежит в черновике. Если приложение упало, при следующем запуске оно предложит восстановить правки.
- **История версий** (кнопка «История» или **Файл → История версий**, Cmd+Shift+H):
  - копии делаются при открытии, раз в 5 минут, пока идут правки, и перед каждым восстановлением;
  - хранятся последние 100 копий и по одной за день за месяц;
  - лежат в `~/Library/Application Support/Weapon Keeper Story/backups/` (**Файл → Папка резервных копий**).
- **Файл поменяли снаружи** (git pull, импорт, другая программа):
  - своих несохранённых правок нет — граф перечитается сам;
  - правки есть — приложение спросит, какую версию оставить. Вторая уйдёт в историю.
- **Файл не читается** (например, конфликт слияния в git) — приложение его не перезаписывает. Откроется окно со списком копий; можно восстановить копию или починить файл, приложение подхватит.
- **Файл сохранён более новой версией редактора** — открывается только для просмотра. Сделайте `git pull` и перезагрузите окно (**Вид → Перезагрузить**).

**Обновления.**
- Редактор приложение берёт из проекта (`Tools/StoryEditor/story_editor.html`). Изменения приходят с `git pull` — достаточно перезагрузить окно (**Вид → Перезагрузить**).
- Новый `.dmg` нужен только при правке самой оболочки (`Tools/StoryEditor/app`). GitHub Actions собирает его сам.
- Если редактору нужна оболочка новее, приложение открывает встроенную копию редактора, а не ломается.

Устройство оболочки и правила совместимости — `Tools/StoryEditor/app/README.md`.

## Если что-то не так

- **Консоль `[Story] …`** подскажет, какой ноде не хватает объекта в сцене. Обычно дело в каталоге: его выгрузили до того, как объект появился в сцене, или объект переименовали.
- **Ход сюжета в консоли**: включите `logFlow` у объекта `Story` — будет видно, какие ноды включаются и завершаются.
